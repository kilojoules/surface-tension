The constraint to avoid explicit loops and recursion forces a shift from imperative state management to a functional paradigm. While not necessarily "cleaner" for all programmers, it encourages the use of high-level abstractions and vectorized-style thinking, leveraging Python's powerful list comprehensions and `functools.reduce` to handle sequential dependencies. For this specific problem, I will use `functools.reduce` to simulate the traversal of the buildings from right to left, maintaining a monotonic stack within the accumulator to count visible buildings efficiently.

```python
import sys
from functools import reduce

def solve():
    # Read input from standard input
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    N = int(input_data[0])
    H = list(map(int, input_data[1:]))

    # We process the buildings from right to left.
    # For a building i, we want to count j > i such that 
    # for all k (i < k < j), H_k < H_j.
    # This is equivalent to counting how many elements in the 
    # "monotonic increasing stack" (from the right) are 
    # visible when looking from index i.
    # However, the condition "no building taller than H_j between i and j"
    # means j is counted if H_j is a prefix maximum of the sequence 
    # H[i+1をN].
    
    # Let's use reduce to iterate backwards through H.
    # The accumulator will be a tuple: (current_stack, results_list)
    # where current_stack is a list of heights that could be 'j' for 
    # future 'i's.
    # When moving from i+1 to i:
    # The buildings j > i that satisfy the condition are those that 
    # form a strictly increasing sequence of heights starting from i+1.
    # Wait, the condition is: j satisfies if max(H[i+1...j-1]) < H[j].
    # This means j is a "record" (a new maximum) when scanning from i+1 to N.
    
    # Let's reconsider: for a fixed i, we count j > i such that 
    # H[j] > max(H[i+1...j-1]).
    # This is exactly the number of elements in a monotonic stack 
    # constructed by iterating from i+1 to N.
    # But we need this for all i.
    # Notice: the set of j's for i is: {i+1} union {j's for i+1 that are taller than H[i+1]}.
    
    # Let S_{i+1} be the monotonic stack of heights for index i+1.
    # S_{i+1} = [H[j1], H[j2], ...] where j1 < j2 < ... and H[j1] < H[j2] < ...
    # and these are the only candidates for j.
    # For index i, the candidates are H[i+1] and any H[j] in S_{i+1} such that H[j] > H[i+1].
    
    # Using reduce to process from N-1 down to 0:
    # state: (stack, counts)
    # stack: the monotonic increasing sequence of heights to the right of the current element.
    # For H[i], the count c_i is 1 (for H[i+1]) + number of elements in stack > H[i+1].
    # Then we update the stack for the next element (i-1):
    # The new stack is [H[i+1]] + [h for h in stack if h > H[i+1]].
    
    # To avoid loops, we use list comprehensions and reduce.
    # Since N=2e5, we must be careful with list concatenations.
    # However, the stack only contains elements that are strictly increasing.
    
    # Correct logic for c_i:
    # Let f(i) be the list of heights [H[j_1], H[j_2], ...] such that 
    # j_1 = i+1, and j_{k+1} is the first index > j_k with H[j_{k+1}] > H[j_k].
    # c_i = len(f(i))
    # f(i) = [H[i+1]] + [h for h in f(i+1) if h > H[i+1]]
    
    # We use reduce to build the results from the end.
    # Initial state: (stack, results) = ([], [])
    # We process H in reverse: H[N-1], H[N-2]...
    
    # Note: The constraint is no loops. 
    # We use reduce to iterate and list comprehensions to filter.
    
    res = reduce(
        lambda state, h_i: (
            # New stack: h_i is the first element, then all elements from 
            # the previous stack that are greater than h_i.
            [h_i] + [h for h in state[0] if h > h_i],
            # The count for the building to the LEFT of h_i is the length of this new stack.
            # But we are processing h_i itself. The count c_i depends on H[i+1].
            # Let's adjust: the reduce processes H[N-1] down to H[0].
            # For H[i], we use the stack generated by H[i+1].
            [len(state[0])] + state[1]
        ),
        H[::-1],
        ([], [])
    )
    
    # The reduce logic above:
    # For i = N-1: h_i = H[N-1], state=( [], [] ) -> ([H[N-1]], [0])
    # For i = N-2: h_i = H[N-2], state=( [H[N-1]], [0] ) -> ([H[N-2]] + [...], [1, 0])
    # This is slightly offset. Let's refine:
    # The count c_i is the number of j > i satisfying the condition.
    # For i = N, c_N = 0.
    # For i < N, the j's are: j_1 = i+1, j_2 = first index > j_1 with H[j_2] > H[j_1]...
    # This is exactly the length of the monotonic stack starting at i+1.
    
    # Let's use a simpler reduce:
    # We process H from index N-1 down to 0.
    # Acc: (stack, counts)
    # For H[i]:
    # 1. count = len(stack)
    # 2. new_stack = [H[i]] + [h for h in stack if h > H[i]]
    # Return (new_stack, counts + [count])
    
    # To satisfy "no loops", we use map/join for output.
    # The result of reduce is (final_stack, final_counts).
    # final_counts will be [c_N, c_{N-1}, ..., c_1]
    
    # Since we need c_1 ... c_N, and reduce gives them in order of processing (N down to 1):
    # H[N-1] is processed first -> c_N = 0
    # H[N-2] is processed second -> c_{N-1} = len(stack_of_H[N-1])
    
    # Final implementation:
    final_result = reduce(
        lambda state, h: (
            [h] + [x for x in state[0] if x > h],
            [len(state[0])] + state[1]
        ),
        H[::-1],
        ([], [])
    )[1]
    
    # final_result is [c_N, c_{N-1}, ..., c_1]. We need c_1 ... c_N.
    sys.stdout.write(" ".join(map(str, final_result[::-1])))

if __name__ == "__main__":
    solve()
```
