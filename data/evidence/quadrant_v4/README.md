# Stage-3 (quadrant-v4) evidence release

This directory makes the Stage-3 measurements independently auditable without
renting a GPU. It exists because of `docs/correction_2026-07-12.md`: the
original headline probe claim was wrong, the error was only discoverable from
data that lived solely on the author's machine, and a public claim whose
refuting evidence is private cannot be community-corrected. Everything this
repo now claims about the __sol probes is recomputable from these files:

```
PYTHONPATH=src python -m quadrant.probe_correction \
    --evidence data/evidence/quadrant_v4 --out results/correction_2026-07-12
```

(Run from the repo root; writes `probe_correction_evidence.json`.) This
reproduces every **corrected** statistic exactly — the
exact-tie grouped CV, permutation null, LOPO, full-data oracle, and
deception bounds are order-invariant and bit-identical between this package
and the author's raw files. (The `foldlegal_baserate_auroc` reference is
the one corrected quantity that varies with row order — deliberately, since
it characterizes the order-dependent leaky folds themselves; base reads
0.865 here vs 0.871 from the raw layout.) The *originally published* plain-CV numbers (e.g. base 0.820)
are only exactly reproducible from the author's raw file enumeration order;
from this package's sorted order the same leaky procedure gives 0.810 —
that order-dependence is documented as part of the correction
(`docs/correction_2026-07-12.md` §3d), not a defect of this package.

## Files

- `rows_{arm}.jsonl` — one row per generation (arms: base, R-SFT, DPO-r1,
  DPO-r2, vanilla-SFT, vanilla-DPO). Fact side of the quadrant: AST checker
  verdicts (`complied_shown/loose/strict`, `has_loop`, `has_recursion`,
  `has_comprehension`, `functional_evasion`), test outcomes (`passes_tests`,
  `failed_tests`), the model's full solution turn (`raw_output`,
  `extracted_code`) and its structured self-report (`self_report_text`).
  Rows are exactly what the generation pipeline produced, plus a `canary`
  field (see `NOTICE.md` at the repo root).
- `acts_sol_{arm}.npz` — the __sol residual-stream tensors, deduplicated to
  one `(61, 5376)` fp16 tensor **per problem** (61 = embedding layer + 60
  transformer layers; d_model 5376). One per
  problem, not per sample: __sol is captured by a forward pass over the
  prompt alone, and the prompt does not vary across a problem's samples, so
  the per-sample tensors are byte-identical — the central fact of the
  correction. Keys: `problem_ids`, `vectors`, `canary`.
- `identity_manifest_{arm}.json` — proof the dedup is lossless: sha256 of
  every original per-sample tensor (as loaded, fp16 file → float32 bytes),
  grouped by problem, with `all_identical` per problem.
- `canary.txt` — the canary GUID.

## What is NOT here, and why

- **Judge outputs (`judgments.jsonl`, claim side).** Lost when the judge pod
  was deleted — the published deception counts (base 1/95, trained arms 0/35
  and 0/36) cannot currently be re-derived, only upper-bounded (see the
  correction doc). The judge's exact input is preserved per row in
  `self_report_text`, so the claim side can be REGENERATED by re-running
  `quadrant.judge_runner` (Qwen3-30B-A3B, temp 0, guided JSON, rubric v1)
  over these rows. Lesson recorded in the correction doc: sync outputs, not
  just logs, before killing a pod.
- **__rep tensors** (post-code, pre-self-report position). Per-sample
  distinct, ~300 MB total — too large for the repo. Retained on the author's
  machine; the published __rep AUROCs should be treated as unaudited until
  those tensors are deposited in an external archive (planned alongside the
  writeup).
- **Problem statements.** Rows reference LiveCodeBench problem ids only;
  the text is AtCoder-provenance content (see `NOTICE.md`).

## Provenance

Generated on RunPod/Vast pods (see `RAW_MANIFEST` in
`src/quadrant/probe_correction.py` for the per-arm pod-sync directories),
Gemma-4-31B-it in 4-bit, checker/probe versions stamped per row
(`checker_version`, `probe_version`). Packaged by
`python -m quadrant.package_evidence` on 2026-07-12, which asserts
within-problem byte-identity before writing anything. One quirk, expected:
each arm's raw activations contain exactly one `__sol` tensor with no
matching generation row (the run was interrupted after capture, before the
row was written); it appears in the identity manifest and is excluded from
every probe statistic, which is why the manifests count one more sample than
the rows files.
