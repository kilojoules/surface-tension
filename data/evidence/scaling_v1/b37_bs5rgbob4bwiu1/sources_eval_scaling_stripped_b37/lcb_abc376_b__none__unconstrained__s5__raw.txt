**Wait**, I noticed a logic error in my `dist_without` function regarding the obstacle. If the obstacle is at the destination, the problem says $T_i \neq r_i$ (for $H_i=L$), so the destination itself is never the obstacle. The obstacle blocks the path if it is any of the nodes *between* the start and the destination.

Let's refine:
Clockwise distance is $d = (e - s) \pmod N$.
The nodes visited are $(s+1)\pmod N, \dots, (s+d)\pmod N$.
The obstacle $obs$ is encountered if $(obs - s) \pmod N \in \{1, \dots, d-1\}$.
Actually, the rule is: "you can do this only if the other hand is not on the destination part."
So if we want to move from $s$ to $e$, and the obstacle is at $obs$, we cannot step on $obs$.
If $(obs - s) \pmod N < d$, then the clockwise path is blocked because we would hit $obs$ before or at the destination. Since $obs \neq e$, we hit it *before*.

Correct logic:
Clockwise distance $d_{cw} = (e - s) \pmod N$.
Counter-clockwise distance $d_{ccw} = (s - e) \pmod N$.
Clockwise path is blocked if $(obs - s) \pmod N < d_{cw}$.
Otherwise, clockwise is clear.
Since it's guaranteed to be achievable, if clockwise is blocked, counter-clockwise must be clear.

def solve():
    # Read all input at once
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    N = int(input_data[0])
    Q = int(input_data[1])
    
    # Parse instructions into a list of (H, T)
    # Using a list comprehension to process the flat input_data list
    instructions = [
        (input_data[i], int(input_data[i+1])) 
        for i in range(2, len(input_data), 2)
    ]

    # Initial state: left hand at 1, right hand at 2 (0-indexed: 0, 1)
    curr_l, curr_r = 0, 1
    total_ops = 0
    
    for h, t in instructions:
        target = t - 1 # Convert to 0-indexed
        
        # Identify which hand is moving and which is the obstacle
        s = curr_l if h == 'L' else curr_r
        obs = curr_r if h == 'L' else curr_l
        e = target
        
        # Calculate distances on the ring
        # Clockwise distance from s to e
        d_cw = (e - s) % N
        # Check if the obstacle is encountered on the clockwise path
        # The obstacle is hit if its relative position from s is less than the distance to e
        if (obs - s) % N < d_cw:
            # Clockwise is blocked, must go counter-clockwise
            dist = (s - e) % N
        else:
            # Clockwise is clear
            dist = d_cw
            
        total_ops += dist
        
        # Update the position of the hand that moved
        if h == 'L':
            curr_l = target
        else:
            curr_r = target
            
    print(total_ops)

Final logic for `dist`:
If we move clockwise, we visit $(s+1)\%N, (s+2)\%N, \dots, (s+d_{cw})\%N$.
The obstacle $obs$ is hit if $(obs-s)\%N \in \{1, \dots, d_{cw}\}$.
Since $obs \neq e$, the condition is simply $(obs-s)\%N < d_{cw}$.
If this is true, we must go counter-clockwise, distance $(s-e)\%N$.
Otherwise, we go clockwise, distance $(e-s)\%N$.
