Actually, the $O(N^2)$ approach is: for every pair of indices $(i, j)$ with the same height, we check the progression. The number of pairs is $\sum \frac{C_h(C_h-1)}{2}$ where $C_h$ is the count of height $h$. This is maximized when one height has all $N$ buildings, giving $3000^2 / 2 \approx 4.5 \times 10^6$ iterations. Inside, the `sum` runs $N/d$ times. In the worst case ($d=1$), it's $O(N)$. That would be $O(N^3)$. 

To optimize to $O(N^2)$, we can use dynamic programming: `dp[i][d]` is the length of the progression ending at index $i$ with difference $d$. But $d$ can be up to 3000.
Actually, for a fixed height, we can use:
`dp[i][d] = dp[i-d][d] + 1` if $H[i] == H[i-d]$.
Since we only care about indices of the same height, let's use a dictionary for DP.

Revised $O(N^2)$ approach:
For each height $h$:
  Indices $I = [i_1, i_2, \dots, i_m]$
  $dp[i][d]$ = length of sequence ending at index $i$ with difference $d$.
  Since we only iterate over $i \in I$, we can use a list of dictionaries.
