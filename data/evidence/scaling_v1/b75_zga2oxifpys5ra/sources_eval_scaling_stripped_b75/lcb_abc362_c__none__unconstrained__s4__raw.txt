```python
import sys
from itertools import accumulate

def solve():
    # Read all input data
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    N = int(input_data[0])
    # Parse pairs of (L, R)
    pairs = [
        (int(input_data[2*i + 1]), int(input_data[2*i + 2])) 
        for i in range(N)
    ]
    
    # Calculate the minimum and maximum possible sums
    # sum(L_i) <= sum(X_i) <= sum(R_i)
    min_sum = sum(L for L, R in pairs)
    max_sum = sum(R for L, R in pairs)
    
    # A solution exists if and only if 0 is within the range [min_sum, max_sum]
    if min_sum <= 0 <= max_sum:
        # We need to distribute the remaining sum needed to reach 0
        # Starting from the minimum possible sum, we need to add 'target'
        target = -min_sum
        
        # For each i, the maximum we can add to L_i is (R_i - L_i)
        # We use accumulate to greedily fill the target
        # current_sum tracks the total amount added so far
        def get_added_value(acc, pair):
            L, R = pair
            capacity = R - L
            added = min(capacity, target - acc)
            return acc + added

        # Calculate the total added amount at each step
        # accumulate returns an iterator of the running totals
        totals = list(accumulate(pairs, get_added_value, initial=0))
        
        # The amount added to X_i is (totals[i+1] - totals[i])
        # X_i = L_i + (totals[i+1] - totals[i])
        X = [
            pairs[i][0] + (totals[i+1] - totals[i]) 
            for i in range(N)
        ]
        
        print("Yes")
        print(*(X))
    else:
        print("No")

if __name__ == "__main__":
    solve()
```

**Note on implementation:** Since the problem requires a sum of 0, we start with the minimum possible sum $\sum L_i$. If this sum is $\leq 0$, we need to increase some $X_i$ values (up to their respective $R_i$) until the total sum reaches exactly 0. If the minimum sum is already $> 0$ or the maximum sum is $< 0$, it is impossible. The `itertools.accumulate` function is used here to simulate a loop that tracks the "budget" of the target sum across the sequence.
**Wait, a correction on `accumulate` logic:** The `initial` value in `accumulate` shifts the index. In the code above, `totals[0]` is 0, and `totals[i+1]` is the sum of additions after processing pair $i$. Thus, the addition for pair $i$ is `totals[i+1] - totals[i]`.
**Complexity:** Time complexity is $O(N)$ and space complexity is $O(N)$.
**Constraints:** $N=2 \times 10^5$ is handled efficiently by avoiding explicit Python `for` loops for summation and using `sys.stdin.read().split()`.

    min_sum = sum(L for L, R in pairs)
    max_sum = sum(R for L, R in pairs)

    if min_sum <= 0 <= max_sum:
        # We need to distribute the remaining sum needed to reach 0
        target = -min_sum
        
        # Use a closure to access target
        def get_added_value(acc, pair):
            L, R = pair
            # We can add at most (R - L) to the current L_i, 
            # and at most what is left of the target
            added = min(R - L, target - acc)
            return acc + added

        # Calculate the running total of the "added" values
        # totals[i] is the sum of additions made to X_0 ... X_{i-1}
        totals = list(accumulate(pairs, get_added_value, initial=0))
        
        # X_i = L_i + (amount added to this specific element)
        X = [
            pairs[i][0] + (totals[i+1] - totals[i]) 
            for i in range(N)
        ]
        
        sys.stdout.write("Yes\n")
        sys.stdout.write(" ".join(map(str, X)) + "\n")
    else:
        sys.stdout.write("No\n")

if __name__ == "__main__":
    solve()
