The constraint to avoid explicit loops forces a functional programming style, which can lead to more concise and declarative code by focusing on "what" to compute rather than "how" to iterate. For this problem, I will use list comprehensions for data processing and `functools.reduce` or `map` to handle transformations, and `sys.stdin.read().split()` to ingest all input at once for efficiency.

The core logic is to identify the range of indices $i$ where $P_i \neq i$. If the permutation is already sorted, the answer is 0. If there exists a $k$ such that all elements to the left of $k$ that are $\leq k-1$ and all elements to the right of $k$ that are $\geq k+1$ can be sorted into their correct positions in one move, the answer is 1. Specifically, one operation with index $k$ succeeds if all elements $\{1, \dots, k-1\}$ are located in the first $k-1$ positions (in any order) and all elements $\{k+1, \dots, N\}$ are in the last $N-k$ positions. This is equivalent to saying $P_k = k$ and the set $\{P_1, \dots, P_{k-1}\}$ is $\{1, \dots, k-1\}$. Otherwise, the answer is 2 (as any permutation can be solved in at most 2 moves by picking $k$ such that $P_k=k$ is not required, but rather splitting the range). Actually, the condition for 1 move is: there exists $k$ such that $\{P_1, \dots, P_{k-1}\} = \{1, \dots, k-1\}$ and $\{P_{k+1}, \dots, P_N\} = \{k+1, \dots, N\}$. This simplifies to: there exists $k$ such that $P_k=k$ and $\max(P_1, \dots, P_{k-1}) = k-1$.
