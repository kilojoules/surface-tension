**Wait**, I noticed a logic error in my `is_on_path1` check. If the other hand is at the start or end position, it blocks the path. But the problem guarantees $T_i \neq r_i$ when $H_i$ is $L$, and $T_i \neq l_i$ when $H_i$ is $R$. Also, the other hand is stationary. So the only way a path is blocked is if the other hand is at some position $k$ between $s$ and $e$. 

Actually, the simplest way to think about it is: the other hand divides the ring into a linear segment. To get from $s$ to $e$ without crossing $o$, you must stay within the segment $(o, o+N)$ (modulo $N$).

Let's refine the distance:
The distance from $s$ to $e$ avoiding $o$ is:
If we move clockwise from $s$ to $e$, the distance is $(e-s) \pmod N$. This path is blocked if $o$ is encountered.
$o$ is encountered if $(o-s) \pmod N < (e-s) \pmod N$.

Corrected logic:
```python
def get_dist(s, e, o, n):
    # Clockwise distance
    d_cw = (e - s) % n
    # Is o encountered moving clockwise?
    # o is encountered if the distance from s to o clockwise is less than s to e.
    if (o - s) % n < d_cw:
        # Must move counter-clockwise
        return (s - e) % n
    else:
        # Can move clockwise
        return d_cw
```

```python
    # The other hand 'o' acts as a barrier.
    def get_dist(s, e, o, n):
        if s == e: return 0
        # Clockwise distance from s to e
        d_cw = (e - s) % n
        # Check if o is between s and e clockwise
        # (o-s)%n is the clockwise distance from s to o
        if (o - s) % n < d_cw:
            # Path is blocked, must go counter-clockwise

            # Path is clear
            return d_cw
```

Final check on `get_dist`:
If $s=1, e=4, o=3, N=6$:
$d_{cw} = (4-1)\%6 = 3$.
$(o-s)\%6 = (3-1)\%6 = 2$.
$2 < 3$ is True $\rightarrow$ blocked $\rightarrow$ return $(1-4)\%6 = 3$.
Correct: $1 \to 6 \to 5 \to 4$.

If $s=1, e=4, o=6, N=6$:
$d_{cw} = 3$.
$(o-s)\%6 = (6-1)\%6 = 5$.
$5 < 3$ is False $\rightarrow$ clear $\rightarrow$ return 3.
Correct: $1 \to 2 \to 3 \to 4$.

The starting positions are $1, 2$, so $o \neq s$ is also guaranteed for the first move.
```python
import sys

# Set recursion limit just in case, though not using recursion
sys.setrecursionlimit(2000)

def solve():
    # Use fast I/O
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    N = int(input_data[0])
    Q = int(input_data[1])
    
    # Extract instructions
    # Each instruction is (Hand, Target)
    insts = [
        (input_data[i], int(input_data[i+1])) 
        for i in range(2, len(input_data), 2)
    ]

    # Distance function to move from s to e avoiding o on a ring of size N
    # Clockwise distance is (e-s)%N. If (o-s)%N is less than that, 
    # the other hand is in the way.
    def calc_dist(s, e, o, n):
        if s == e: return 0
        cw_dist = (e - s) % n
        if (o - s) % n < cw_dist:
            return (s - e) % n
        return cw_dist

    # Simulation using a loop to update state (l, r, total_dist)
    # Initial state: Left=1, Right=2, Total=0
    def run_simulation(instructions, n):
        l, r, total = 1, 2, 0
        for h, t in instructions:
            if h == 'L':
                total += calc_dist(l, t, r, n)
                l = t
            else:
                total += calc_dist(r, t, l, n)
                r = t
        return total

    print(run_simulation(insts, N))

if __name__ == "__main__":
    solve()
```
