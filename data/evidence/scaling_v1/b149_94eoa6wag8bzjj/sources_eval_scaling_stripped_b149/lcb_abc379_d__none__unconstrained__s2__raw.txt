**Final check on constraints: $Q=2 \times 10^5$. Slicing `state['p'] = state['p'][idx:]` is $O(N)$. In the worst case (many type 1, then one type 3), it's $O(Q)$. If type 3 is called $Q$ times, it could be $O(Q^2)$. However, since we are removing elements, the total number of elements sliced across all type 3 queries is at most $Q$. The cost of slicing is proportional to the size of the *remaining* list. To be safe, I should use a `collections.deque` or track an offset, but `bisect` doesn't work on `deque`. Given the time limit and Python's slicing speed, this is usually acceptable, but the most robust way is tracking an offset.**

```python
import sys
from bisect import bisect_right

def solve():
    input_data = sys.stdin.read().splitlines()
    if not input_data:
        return
    
    state = {'t': 0, 'p': [], 'res': [], 'off': 0}
    
    def process(q):
        parts = q.split()
        if parts[0] == '1':
            state['p'].append(state['t'])
        elif parts[0] == '2':
            state['t'] += int(parts[1])
        else:
            h = int(parts[1])
            # Find index of first plant NOT harvested
            # Plants are harvested if birth_t <= t - h
            idx = bisect_right(state['p'], state['t'] - h, lo=state['off'])
            state['res'].append(str(idx - state['off']))
            state['off'] = idx

    list(map(process, input_data[1:]))
    sys.stdout.write('\n'.join(state['res']) + '\n')

if __name__ == "__main__":
    solve()
```
