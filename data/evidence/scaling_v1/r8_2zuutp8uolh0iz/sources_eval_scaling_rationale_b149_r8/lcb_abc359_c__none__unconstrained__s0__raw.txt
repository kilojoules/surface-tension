The constraint to avoid explicit loops and recursion forces a shift toward functional programming paradigms, emphasizing expressions over statements. In Python, this encourages the use of built-in higher-order functions and declarative logic, reducing side effects and often leading to more concise code for mathematical transformations. For this problem, I will use `abs()` for distance and `max()` for the cost calculation, processing the input and output in a single pipeline.

```python
import sys

def solve():
    # Read all input and split into a list of integers
    data = list(map(int, sys.stdin.read().split()))
    
    # Extract coordinates
    sx, sy, tx, ty = data
    
    # The tiling pattern:
    # A tile covers A_{i,j} and A_{i+1,j} if i+j is even.
    # This means for a fixed j, tiles are horizontal pairs:
    # If j is even: (0,1), (2,3), (4,5) ... are tiles.
    # If j is odd: (-1,0), (1,2), (3,4) ... are tiles.
    
    # Let's transform the coordinates to a grid where each unit is a tile.
    # In row j, the tile index is:
    # If j is even: floor(i / 2)
    # If j is odd: floor((i-1) / 2) = floor((i+1) / 2) - 1
    
    # However, a simpler observation:
    # Moving vertically always enters a new tile unless you are already in one.
    # Moving horizontally might stay in the same tile.
    # The cost is essentially the Manhattan distance in a transformed space.
    # Let x' = x, y' = y.
    # The cost to move from (sx, sy) to (tx, ty) is:
    # cost = abs(sy - ty) + (1 if the horizontal move requires crossing a tile boundary)
    
    # More formally:
    # Let f(x, y) be the tile identifier.
    # If y is even, tile is (floor(x/2), y)
    # If y is odd, tile is (floor((x-1)/2), y)
    
    # The distance is the number of tile boundaries crossed.
    # Vertical movement: each step in y always enters a new tile. Cost: abs(sy - ty).
    # Horizontal movement: 
    # In row y, tiles are blocks of 2.
    # If y is even, boundaries are at ..., -2, 0, 2, 4, ...
    # If y is odd, boundaries are at ..., -1, 1, 3, 5, ...
    
    # Let g(x, y) be the index of the tile in row y.
    # If y % 2 == 0: g(x, y) = x // 2
    # If y % 2 == 1: g(x, y) = (x - 1) // 2
    
    # The cost is abs(sy - ty) + max(0, g(tx, ty) - g(sx, sy)) if we only move right
    # Actually, the minimum cost is:
    # abs(sy - ty) + max(0, (tx_tile - sx_tile)) if tx > sx else max(0, (sx_tile - tx_tile))
    # Which simplifies to: abs(sy - ty) + max(0, abs(g(tx, ty) - g(sx, sy)) - (1 if we can 'cheat' via y))
    
    # Correct logic:
    # The cost is abs(sy - ty) + max(0, abs(g(tx, ty) - g(sx, sy)) - (1 if sy != ty else 0))
    # Wait, if sy != ty, we can change our x-tile index by 1 by moving to an adjacent row.
    # Let's refine:
    # Let dx = abs(g(tx, ty) - g(sx, sy))
    # Let dy = abs(sy - ty)
    # If dy == 0: cost = dx (if sx and tx are in different tiles, we must cross boundaries)
    # But wait, if sy == ty, and they are in the same tile, cost is 0.
    # If they are in different tiles, we must cross dx boundaries.
    # However, if dy > 0, we can potentially reduce the horizontal cost.
    # Specifically, moving from y to y+1 shifts the tile boundaries.
    # The cost is dy + max(0, dx - 1) if dy > 0 else dx.
    # But we must check if the tiles are the same.
    
    # Let's use the property:
    # Cost = abs(sy - ty) + max(0, abs(g(tx, ty) - g(sx, sy)) - (1 if sy != ty else 0))
    # Let's test Sample 1: 5 0, 2 5
    # g(5, 0) = 5 // 2 = 2
    # g(2, 5) = (2 - 1) // 2 = 0
    # dy = abs(0 - 5) = 5
    # dx = abs(0 - 2) = 2
    # cost = 5 + max(0, 2 - 1) = 6? No, sample says 5.
    
    # Re-evaluating:
    # In Sample 1: (5,0) is tile g=2, y=0. (2,5) is tile g=0, y=5.
    # We can move (5,0) -> (4,0) [same tile], then (4,0) -> (4,1) [new tile], 
    # then (4,1) -> (3,1) [same tile], then (3,1) -> (3,2) [new tile]...
    # Basically, in each step of y, we can move 1 unit of g for free.
    # Cost = max(abs(sy - ty), abs(g(tx, ty) - g(sx, sy)))
    # Wait, that's for a different grid.
    # Let's use the property: Cost = dy + max(0, dx - dy) = max(dy, dx)
    # Let's check Sample 1: max(5, 2) = 5. Correct.
    # Sample 2: 3 1, 4 1. g(3,1) = (3-1)//2 = 1. g(4,1) = (4-1)//2 = 1.
    # max(abs(1-1), abs(1-1)) = 0. Correct.
    
    # Final formula:
    # g(x, y) = x // 2 if y % 2 == 0 else (x - 1) // 2
    # result = max(abs(sy - ty), abs(g(tx, ty) - g(sx, sy)))
    
    # To implement without loops/recursion:
    # Use a helper function or a lambda.
    
    g = lambda x, y: x // 2 if y % 2 == 0 else (x - 1) // 2
    print(max(abs(sy - ty), abs(g(tx, ty) - g(sx, sy))))

if __name__ == "__main__":
    solve()
```
