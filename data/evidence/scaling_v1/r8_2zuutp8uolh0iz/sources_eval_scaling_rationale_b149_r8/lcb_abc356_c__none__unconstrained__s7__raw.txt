The constraint to avoid explicit `for` and `while` loops forces a shift from imperative programming to a functional paradigm. This encourages the use of declarative constructs that describe *what* the result should be rather than *how* to step through the process, leveraging Python's powerful comprehension syntax and built-in higher-order functions. To solve this problem, I will use `itertools.product` to generate all possible key combinations, list comprehensions to filter these combinations based on the test results, and `sum` to count the valid ones.

```python
import sys
from itertools import product

def solve():
    # Read all input at once
    input_data = sys.stdin.read().split()
    if not input_data:
        return

    # Parse N, M, K
    N = int(input_data[0])
    M = int(input_data[1])
    K = int(input_data[2])

    # Parse tests
    # Each test is stored as (set_of_keys, result)
    # We use a helper function to slice the input list to handle variable C_i
    def parse_tests(data, index, count):
        if count == 0:
            return []
        
        # C_i is at data[index]
        c_i = int(data[index])
        # Keys are from index + 1 to index + c_i
        keys = set(map(int, data[index + 1 : index + 1 + c_i]))
        # Result is at index + 1 + c_i
        res = data[index + 1 + c_i]
        
        return [(keys, res)] + parse_tests(data, index + 2 + c_i, count - 1)

    # Since recursion depth might be an issue and loops are forbidden, 
    # we can use a different approach to parse tests using a list comprehension 
    # if we can determine the boundaries. However, the C_i makes it dynamic.
    # Let's use a trick with a generator or a custom reduce-like structure.
    # Actually, the simplest way to parse this without loops is to 
    # pre-process the input into a format we can handle.
    
    # Because we cannot use while/for, we use a recursive-like 
    # structure via a list comprehension and a helper.
    # But wait, the constraint allows map/filter/reduce.
    # Let's redefine the parsing logic to be loop-free.
    
    def get_tests():
        # We use a list to store the current pointer and update it
        # But we can't use while. Let's use a recursive function.
        # Python's recursion limit is usually 1000, M is 100. This is safe.
        def recurse(idx, remaining):
            if remaining <= 0:
                return []
            c_i = int(input_data[idx])
            keys = set(map(int, input_data[idx + 1 : idx + 1 + c_i]))
            res = input_data[idx + 1 + c_i]
            return [(keys, res)] + recurse(idx + 2 + c_i, remaining - 1)
        return recurse(3, M)

    tests = get_tests()

    # Generate all 2^N combinations of real (1) and dummy (0) keys
    # combinations is an iterator of tuples, e.g., (0, 1, 0, ...)
    all_combinations = product([0, 1], repeat=N)

    # A combination is valid if for every test:
    # If R_i == 'o', sum of real keys in the set >= K
    # If R_i == 'x', sum of real keys in the set < K
    
    def is_valid(combo):
        # combo is a tuple of 0/1. Key j is at index j-1.
        # We check if all tests are satisfied.
        # We use all() to avoid loops.
        return all(
            (sum(combo[k-1] for k in test_keys) >= K) if res == 'o' 
            else (sum(combo[k-1] for k in test_keys) < K)
            for test_keys, res in tests
        )

    # Count valid combinations using sum() and a generator expression
    result = sum(1 for combo in all_combinations if is_valid(combo))
    print(result)

if __name__ == "__main__":
    solve()
```
