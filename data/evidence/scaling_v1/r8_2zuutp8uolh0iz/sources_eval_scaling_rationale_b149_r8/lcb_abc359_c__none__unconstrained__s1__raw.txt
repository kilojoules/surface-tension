The constraint to avoid explicit loops and recursion forces a shift from imperative to functional programming styles, encouraging the use of high-level abstractions that often map better to mathematical definitions. For this problem, since the cost is determined by a closed-form coordinate transformation, I will use direct arithmetic expressions to calculate the minimum toll.

```python
import sys

def solve():
    # Read input from standard input
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    sx, sy = map(int, input_data[0:2])
    tx, ty = map(int, input_data[2:4])

    # The tiling pattern is based on the parity of i+j.
    # When i+j is even, A_{i,j} and A_{i+1,j} are one tile.
    # This means tiles are 2x1 blocks aligned horizontally.
    # Specifically, for a fixed j:
    # If j is even, tiles are [0,1]U[1,2], [2,3]U[3,4]... (i=0,2,4...)
    # If j is odd, tiles are [-1,0]U[0,1], [1,2]U[2,3]... (i=-1,1,3...)
    
    # Let's transform the coordinates to a grid where each unit is a tile.
    # For a cell (i, j), the tile index is:
    # If j is even: tile_x = i // 2, tile_y = j
    # If j is odd:  tile_x = (i + 1) // 2, tile_y = j
    # However, the cost to move between tiles is the Manhattan distance 
    # in a transformed coordinate system.
    
    # Let's redefine the grid:
    # A cell (i, j) belongs to tile (X, Y) where:
    # Y = j
    # X = (i + (j % 2)) // 2
    
    # The cost to move from (sx, sy) to (tx, ty):
    # Moving in Y direction always enters a new tile.
    # Moving in X direction might stay in the same tile or enter a new one.
    # The distance is effectively the L1 distance in the transformed (X, Y) space,
    # but we must account for the fact that moving diagonally in the original 
    # grid can sometimes be cheaper.
    
    # The cost is max(|X1 - X2|, |Y1 - Y2|) if we could move diagonally,
    # but we can only move axis-aligned.
    # Actually, the problem is simpler: 
    # To change Y by 1, you must enter a new tile.
    # To change X, you might enter new tiles.
    # The minimum cost is max(|X1 - X2|, |Y1 - Y2|) is for 8-connectivity.
    # For 4-connectivity (up, down, left, right), the cost is:
    # Let dx = |X1 - X2| and dy = |Y1 - Y2|.
    # The cost is dy + dx if we move purely orthogonally.
    # But we can move 1 unit in X and 1 unit in Y and potentially 
    # "save" a toll if the tiles are aligned.
    
    # Correct logic for this specific tiling:
    # The distance is max(|X1 - X2|, |Y1 - Y2|) if we can move diagonally.
    # But we can't. However, we can move 1 unit X, then 1 unit Y.
    # The cost is actually simply:
    # cost = max(|X1 - X2|, |Y1 - Y2|) is NOT correct.
    # The cost is |Y1 - Y2| + max(0, |X1 - X2| - 0) ... no.
    
    # Let's use the property:
    # Cost = max(|X1 - X2|, |Y1 - Y2|) is for Chebyshev distance.
    # Here, moving 1 unit in Y always costs 1.
    # Moving 1 unit in X costs 1 every 2 units (roughly).
    # The distance is actually:
    # dist = max(|X1 - X2|, |Y1 - Y2|) if we can move diagonally.
    # Since we can move n units in one direction, we can simulate a diagonal 
    # move by moving 1 unit X then 1 unit Y.
    # The cost to move from (X1, Y1) to (X2, Y2) is max(|X1 - X2|, |Y1 - Y2|).
    # Wait, if we move from (0,0) to (1,1), we move X then Y.
    # Tile (0,0) -> Tile (1,0) [cost 1] -> Tile (1,1) [cost 1]. Total 2.
    # But if we move Y then X:
    # Tile (0,0) -> Tile (0,1) [cost 1] -> Tile (1,1) [cost 1]. Total 2.
    # Actually, the cost is simply |X1 - X2| + |Y1 - Y2|? 
    # No, Sample 1: (5,0) to (2,5). 
    # S: X = (5 + 0)//2 = 2, Y = 0. 
    # T: X = (2 + (5%2))//2 = (2+1)//2 = 1, Y = 5.
    # |2-1| + |0-5| = 1 + 5 = 6. Sample output says 5.
    # If we use max(|X1-X2|, |Y1-Y2|), we get max(1, 5) = 5.
    # Let's check Sample 2: (3,1) to (4,1).
    # S: X = (3+1)//2 = 2, Y = 1.
    # T: X = (4+1)//2 = 2, Y = 1.
    # max(0, 0) = 0. Correct.
    
    # Why is it max(|X1-X2|, |Y1-Y2|)?
    # Because we can move 1 unit in X and 1 unit in Y and only pay 1 toll 
    # if we transition through a shared boundary.
    # Specifically, from tile (X, Y), moving to (X+1, Y+1) can be done by:
    # (X, Y) -> (X+1, Y) -> (X+1, Y+1) [2 tolls]
    # OR (X, Y) -> (X, Y+1) -> (X+1, Y+1) [2 tolls]
    # Wait, the sample 1 explanation says:
    # Move left 1 (0 toll), up 1 (1 toll), left 1 (0 toll), up 3 (3 tolls), left 1 (0 toll), up 1 (1 toll).
    # Total = 0+1+0+3+0+1 = 5.
    # This confirms the cost is max(|X1-X2|, |Y1-Y2|).
    
    x1 = (sx + (sy % 2)) // 2
    y1 = sy
    x2 = (tx + (ty % 2)) // 2
    y2 = ty
    
    print(max(abs(x1 - x2), abs(y1 - y2)))

if __name__ == "__main__":
    solve()
```
