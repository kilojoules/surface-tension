The constraint to avoid explicit loops forces a shift from imperative state-mutation to a functional paradigm, emphasizing the transformation of data streams. In this specific problem, the goal is to find the minimum number of operations to sort a permutation. An operation at index $k$ sorts everything to the left and everything to the right of $k$. This means if we can find a $k$ such that $P_k = k$ and all elements $\{1, \dots, k-1\}$ are located in the first $k-1$ positions (though not necessarily sorted) and all elements $\{k+1, \dots, N\}$ are in the remaining positions, one operation suffices. However, the operation actually sorts the ranges, so we simply need to check if there exists a $k$ such that $P_k = k$ and the set of elements $\{P_1, \dots, P_{k-1}\}$ is exactly $\{1, \dots, k-1\}$. If the array is already sorted, the answer is 0. If such a $k$ exists, the answer is 1. Otherwise, it can be proven that for $N \ge 3$, the answer is at most 2.

To implement this without loops, I will use `functools.reduce` to maintain a running state (the maximum value encountered so far) and list comprehensions with `any()` to evaluate the conditions.
