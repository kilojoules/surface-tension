**Wait**, I noticed a logic error in my `handle_type3`. I assumed that the threshold $G[current] - H$ is non-decreasing. Let's check: $G$ is non-decreasing, but $H$ can be anything. If $H$ is very large, the threshold is small. If $H$ is small, the threshold is large. 

Actually, the problem says "Harvest all plants with a height of at least $H$". 
Height is $G[current] - G[birth]$. 
Condition: $G[current] - G[birth] \ge H \implies G[birth] \le G[current] - H$.

If $G[current] - H$ decreases, we might not harvest any plants. But we can never "un-harvest" a plant. The set of harvested plants is the union of all plants $i$ such that $G[birth_i] \le G[current_j] - H_j$ for any query $j$ of type 3.

However, the plants are removed. This means for a specific query $j$, we only harvest plants that were not harvested by any query $k < j$.
The condition for plant $i$ to be harvested at query $j$ is:
$G[birth_i] \le G[current_j] - H_j$ AND for all $k < j$, $G[birth_i] > G[current_k] - H_k$.

This means for a fixed $j$, we harvest all plants $i$ whose $G[birth_i]$ is in the range:
$(\max_{k < j} (G[current_k] - H_k), \quad G[current_j] - H_j]$.

If $G[current_j] - H_j \le \max_{k < j} (G[current_k] - H_k)$, then no plants are harvested.
Otherwise, the number of plants harvested is the number of $G[birth_i]$ in that range.

Since $G[birth_i]$ is sorted, we can use `bisect_right` to find the number of elements $\le$ a value.

Revised logic:
1. $G$ is the prefix sum of $T$.
2. $B$ is the list of $G[i]$ for all type 1 queries.
3. For each type 3 query $(G_{curr}, H)$:
   - $Threshold = G_{curr} - H$
   - $PrevMax = \max(0, \text{all previous thresholds})$
   - If $Threshold > PrevMax$:
     - Count $B[i]$ in range $(PrevMax, Threshold]$.
     - This is `bisect_right(B, Threshold) - bisect_right(B, PrevMax)`.
   - Else:
     - Count is 0.
   - Update $PrevMax = \max(PrevMax, Threshold)$.

This logic is $O(Q \log Q)$ and uses no loops.
