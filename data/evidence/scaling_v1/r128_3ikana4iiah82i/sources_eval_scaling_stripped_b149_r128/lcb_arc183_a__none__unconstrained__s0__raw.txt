One final check on the logic:
The total number of sequences $S = \frac{(NK)!}{(K!)^N}$.
We want the $\lfloor (S+1)/2 \rfloor$-th sequence.
At each position, we determine the digit $d$ by checking how many sequences start with digits $1, 2, \dots, d-1$.
If the sum of these is less than the current rank, and adding the sequences starting with $d$ makes it $\ge$ rank, then $d$ is the correct digit.

The time complexity:
$NK$ positions. At each position, we check up to $N$ digits.
Calculating `get_ways` takes $O(N)$ (for the product).
Total complexity: $O(N^2 K)$.
With $N, K = 500$, $N^2 K = 125,000,000$. This might be slow in Python.
However, we can optimize `get_ways`.
$\text{Ways}(\text{counts}) = \frac{(\sum c_i)!}{\prod c_i!}$.
When we move from one digit to the next in the `ways_per_digit` list, the total sum is the same, and only one $c_i$ changes. But we are iterating through different digits $j$ for the *same* position.
Actually, for a fixed position, the total sum $\sum c_i$ is constant for all $j$.
The only thing that changes is which $c_j$ is decremented.
